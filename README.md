# BloodHelper — правила модулей

Для обновлённых сборок BloodHelper 1.2.0 редактируйте **[policy-v2.json](policy-v2.json)**.
Старый `policy.json` оставлен для прежних клиентов: они не поддерживают запреты по адресу сервера.

У каждого модуля есть четыре параметра:

```json
"inventoryProfiles": {
  "allowed": true,
  "enabled": true,
  "ips": true,
  "banned-ips": [
    "bloodstone.gg",
    "*.bloodstone.gg"
  ]
}
```

- `allowed: false` или `enabled: false` запрещает модуль везде.
- `ips: true` включает запрет на серверах из `banned-ips`. Это значение по умолчанию, в том числе если поле не указано.
- `ips: false` игнорирует список `banned-ips`, но не отменяет общий запрет через `allowed` / `enabled`.
- `banned-ips: []` не добавляет серверных ограничений.
- Разрешённый модуль включается только по личной настройке игрока. GitHub не включает его автоматически.

Сейчас только у `inventoryProfiles` заполнен `banned-ips`: раскладки инвентаря запрещены на Bloodstone. Остальные списки пусты.

## Как указывать серверы

| Запись | Действие |
|---|---|
| `bloodstone.gg` | Этот домен на любом порту |
| `*.bloodstone.gg` | Поддомены, включая вложенные; сам `bloodstone.gg` добавляется отдельно |
| `play.example.org:25566` | Только этот домен и этот порт |
| `192.0.2.10` | Этот IP на любом порту |
| `[2001:db8::10]:25565` | Этот IPv6-адрес и этот порт |

Адрес без явно указанного порта при подключении означает стандартный порт Minecraft 25565.
Регистр домена и завершающая точка не влияют на сравнение. `bloodstone.gg` не совпадает с `bloodstone.gg.example.org`.
Сравнивается адрес, с которым игрок вошёл в мультиплеер. DNS/SRV не разрешаются для поиска других имён сервера: нужные альтернативные домены и IP надо перечислить отдельно.
Одиночный мир не попадает под `banned-ips`. Адрес сервера не отправляется на GitHub.

## Применение

1. Измените нужный модуль в `policy-v2.json` и увеличьте `revision` на 1.
2. Сохраните коммит в `main`. Используйте корректный JSON: двойные кавычки, без комментариев и лишней запятой после последнего элемента.
3. Обновлённые клиенты проверяют правила при запуске и далее раз в 5 минут; кеш GitHub может добавить задержку.

Переход между серверами обновляет ограничения на клиенте сразу. В меню показывается «Запрещено на этом сервере». Личный конфиг и сохранённые раскладки остаются на месте; при выходе с запрещённого сервера личный выбор восстанавливается.

При ошибке сети действуют прежний Safe Mode и последние серверные ограничения текущего сеанса. До первой успешной загрузки в клиент встроен запрет раскладок на `bloodstone.gg` и его поддоменах. Правила других адресов из GitHub загружаются после восстановления доступа; они не сохраняются между перезапусками.

Для этой функции нужны обновлённые JAR с поддержкой `policy-v2.json`. Ранее выпущенные JAR, в том числе с тем же номером 1.2.0, продолжают читать старый `policy.json` и новый запрет не применяют.
`updates` — подсказка о опубликованных версиях; JAR автоматически не устанавливается.
